    Installation

    Get both applications running locally, then turn the site into your own: name, logo, gateways, storage, and the texts your visitors read before they buy.

    Eight sections. The fastest path is to follow the two install lists in order; the environment and media sections explain the values you are pasting in.

    What you need

    Both applications can run on a single small server. Nothing here needs Redis, a message queue service, or a CDN.

    Requirement Details
    PHP 8.2+ With the standard Laravel extensions: ctype, curl, dom, fileinfo, filter, hash, mbstring, openssl, pdo, session, tokenizer, xml. Add gd if certificates should embed images.
    Composer 2 For the backend dependencies.
    Node.js 18.18+ Node 20 or 22 LTS recommended. The storefront is built with npm.
    Database MySQL 8 or MariaDB 10.4+ (required). The Docker stack starts its own MySQL; on a manual install, run one yourself and create an empty database.
    Web server Anything that serves PHP, with the document root pointing at the Laravel public/ directory. php artisan serve is enough while developing.
    Disk space Roughly 500 MB for code and dependencies, plus whatever your video library needs. Moving media to a bucket keeps the server small.

    Optional services

    Each of these unlocks a feature and can be added later, one at a time:

    • Payment gateway accounts — Stripe, PayPal, Mollie, or Razorpay. Without one, only free and fully discounted courses can be taken.
    • SMTP credentials — email verification, password resets, and instructor notifications. Without them, mail is written to storage/logs/laravel.log.
    • An S3-compatible bucket — AWS S3, Cloudflare R2, MinIO, DigitalOcean Spaces, or Wasabi, for lesson videos and attachments.
    • Google OAuth client — the "continue with Google" button on the sign-in page.

    Install the backend

    Run everything below from inside the localhost/ folder — that folder is the Laravel application root.

    1. Install the PHP dependencies

      cd localhost
composer install

      Add --no-dev --optimize-autoloader on a production server.

    2. Create the environment file

      cp .env.example .env
php artisan key:generate

      The next two sections explain which values to change: the database now, everything else as you need it.

    3. Point it at your database

      Create an empty database and a user that can write to it, then set the database block in .env:

      DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=lms
DB_USERNAME=lms_user
DB_PASSWORD=

      Leave QUEUE_CONNECTION, CACHE_STORE, and SESSION_DRIVER as they are — all three use the database and need no extra service.

    4. Create the tables and seed the starting content

      php artisan migrate --seed

      The seeders create the homepage content blocks, the feature list shown on the landing page, and one administrator account.

      Choose the administrator credentials before seeding

      The account comes from ADMIN_EMAIL and ADMIN_PASSWORD in .env, and both are required: the seeder throws an error instead of inventing a password or falling back to a shipped account. No installation shares credentials with another.

    5. Link the public storage directory

      php artisan storage:link

      This makes files on the public disk — the logo and favicon you upload in the panel — reachable from the browser.

    6. Start it and sign in

      php artisan serve

      The API answers on http://localhost:8000/api/v1 and the admin panel on http://localhost:8000/admin. Sign in with the administrator account you seeded.

      Keep a queue worker running whenever queued mail and notifications matter, in a second terminal during development:

      php artisan queue:work

    Environment reference

    Every value below lives in localhost/.env. The ones marked as required for the storefront are what make cookie login work; getting them wrong shows up as a 419 error on the sign-in page.

    Key What it does Local development
    APP_URL The backend's own address. Used for OAuth callbacks, webhook URLs, and certificate links. http://localhost:8000
    FRONTEND_URL Where the browser is sent back to after Google sign-in. http://localhost:3000
    SANCTUM_STATEFUL_DOMAINS Hosts allowed to log in with the session cookie. Must contain the exact host and port of the storefront, or sign-in silently fails. localhost,localhost:3000,127.0.0.1:3000
    CORS_ALLOWED_ORIGINS Origins allowed to call the API from the browser. Must match the storefront origin. http://localhost:3000
    SESSION_DOMAIN Cookie scope. Leave as null when the two apps run on different ports; use .example.com when they share a domain. null
    SESSION_SECURE_COOKIE Send the session cookie over HTTPS only. Turn on in production. false
    LESSON_VIDEO_DISK Where lesson videos and previews are stored: private (local), public, videos, or s3. private
    LESSON_ATTACHMENT_DISK Downloads attached to lessons. Optional — falls back to the video disk. unset (shares video disk)
    VIDEO_SERVING_MODE proxy streams bytes through PHP; signed redirects the browser to a time-limited bucket URL. proxy
    AWS_* Key, secret, region, bucket, and optional endpoint for an S3-compatible bucket. Required when the video disk is s3. empty
    STRIPE_* Optional fallback for the Stripe secret key and webhook signing secret. Every gateway credential — including the Stripe signing secret — is normally saved in the admin panel, which takes priority over these values. PayPal, Mollie, and Razorpay credentials exist only in the panel. empty
    GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET Fallback for Google sign-in. Values saved in the panel take priority. empty
    MAIL_* Mail transport and sender address. log (writes to the log instead of sending)
    After editing .env

    Laravel caches configuration. When a change does not seem to take effect, run php artisan optimize:clear and reload.

    Where lesson media lives

    Videos and attachments are stored on a disk that is not publicly reachable, and delivered only to people who are allowed to watch them. Two decisions control that.

    The disk

    private keeps files on the server under the private storage directory, which is the simplest setup and costs nothing. Switching LESSON_VIDEO_DISK to s3 moves new uploads to a bucket — any S3-compatible provider works, and the endpoints for R2, MinIO, and Spaces are listed in .env.example.

    The bucket must stay private

    Do not mark the bucket public or give it a public base URL: lesson videos would then be downloadable by anyone who guesses a path. The application either streams the bytes itself or issues a short-lived signed URL.

    How video reaches the browser

    Mode Behaviour When to use it
    proxy PHP streams the file after checking that the viewer is enrolled. Videos stay on their private disk and no URL is ever exposed. Default. Best for small audiences and local disks.
    signed The API redirects to a bucket URL that expires after VIDEO_SIGNED_URL_TTL minutes (30 by default). Bandwidth goes straight from the bucket to the viewer. Production with a bucket and real traffic. Falls back to proxying automatically when the disk cannot sign URLs.

    Moving existing files to a bucket

    Uploads made before the switch stay where they were. Copy them across with the included command, then set the disk to s3:

    php artisan media:migrate-to-cloud --target=s3

    The admin panel's Storage page mirrors all of these settings and writes them back to the same configuration, with a connection test and a report of what is stored where. Values saved in the panel take priority over the .env entries.

    Install the storefront

    Run these from the frontend/ folder.

    1. Install the Node dependencies

      npm install

    2. Create the environment file

      NEXT_PUBLIC_API_PROD_URL=http://localhost:8000
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_SITE_URL=http://localhost:3000
NEXT_PUBLIC_MEDIA_HOSTS=

      The two API values are the backend origin only — the /api/v1 part is added by the code, so including it here produces 404s. NEXT_PUBLIC_SITE_URL is the storefront's own address and is only used for SEO links.

      Variable Purpose
      NEXT_PUBLIC_API_PROD_URL Base URL for every API call, including the CSRF cookie request.
      NEXT_PUBLIC_API_URL Allows images served by the backend to load through next/image.
      NEXT_PUBLIC_SITE_URL Public origin of the storefront itself (https://www.example.com), used for /sitemap.xml, /robots.txt and canonical/Open Graph URLs. Leave it out in development to use http://localhost:3000.
      NEXT_PUBLIC_MEDIA_HOSTS Comma-separated extra hosts for images that come straight from a bucket or CDN, for example my-bucket.s3.eu-west-1.amazonaws.com. Leave empty when the backend serves them.
      These are baked in at build time

      Next.js inlines NEXT_PUBLIC_* values when the app is built. Restart the development server after editing .env.local, and rebuild before deploying a change.

    3. Run it

      npm run dev

      The site is on http://localhost:3000. Use npm run dev:tls instead if you need an HTTPS development origin — some gateways and OAuth providers insist on it.

      For production:

      npm run build
npm start
    Build with the backend reachable

    Several public pages are server-rendered with live API data, and npm run build pre-renders them. If the backend is not running at build time, the build stops on a fetch failed error for a page such as /instructors. Start the API first.

    First run in the admin panel

    With both applications running and an administrator signed in at /admin, work down this list. Each row is a page in the panel; the last chapter describes every page in detail.

    Panel page What to set
    Settings → General Settings Site name (used in page titles, the footer, the panel brand, and certificates), logo, favicon.
    Settings → Payment Gateways Enable the gateways you use and paste their keys. Register the Stripe webhook at {APP_URL}/api/v1/webhooks/stripe and the Mollie one at {APP_URL}/api/v1/webhooks/mollie.
    Settings → Payout Methods Instructor commission percentage, the minimum payout amount, and the payout methods instructors may choose from.
    Settings → Social Login Google client ID and secret. Register {APP_URL}/auth/google/callback as the redirect URI in the Google console — the panel shows the exact value to copy.
    Settings → Storage Lesson media disk, delivery mode, and bucket credentials. Use the connection test before uploading a large course.
    Content → Homepage Content The landing page sections and their text and images.
    Content → Footer Footer columns, links, and social icons.
    Content → Terms & Privacy The terms of service and privacy policy, each with its own title and rich-text body. They render at /terms and /privacy-policy.
    Content → Cookie Consent The consent banner: heading, body, button labels, and the label of the cookie policy link.
    Courses → Categories At least one category before courses can be published.

    Going live

    Work through this before pointing a domain at the installation.

    • Set APP_ENV=production, APP_DEBUG=false, and real HTTPS values for APP_URL, FRONTEND_URL, SANCTUM_STATEFUL_DOMAINS, and CORS_ALLOWED_ORIGINS. Turn on SESSION_SECURE_COOKIE.
    • Point the web server's document root at the Laravel public/ folder, never at the application root.
    • Build the storefront with production API URLs, then run it behind the same TLS setup.
    • Run composer install --no-dev --optimize-autoloader and php artisan optimize on the server.
    • Keep one queue worker alive under a process supervisor, for example php artisan queue:work --tries=3 --timeout=120, and restart it on each deploy.
    • Register the scheduler with a single cron entry: * * * * * cd /path/to/app && php artisan schedule:run >> /dev/null 2>&1.
    • Register both webhook endpoints with the gateways you enabled, and send a test event to confirm they are accepted.
    • Move lesson media to a private bucket, then verify playback and a download as an enrolled student.
    • Schedule backups of the database and the bucket. Certificates and orders live in the database; losing either is unrecoverable.

    When something does not work

    The failures below cover almost every setup problem reported at this stage.

    Symptom Cause and fix
    Sign-in returns 419, or the account is "unauthenticated" right after logging in The storefront origin is not trusted by the backend. Add the exact host and port to SANCTUM_STATEFUL_DOMAINS and CORS_ALLOWED_ORIGINS, make sure FRONTEND_URL matches, then run php artisan optimize:clear.
    Uploaded images from a bucket never appear Their host is not in the image allow-list. Add it to NEXT_PUBLIC_MEDIA_HOSTS and restart or rebuild the storefront — next.config.mjs reads this file at startup.
    A lesson video returns 404 or 403 The file is not on the configured disk. Check LESSON_VIDEO_DISK and the bucket credentials on the panel's Storage page, and use the connection test. Signed mode falls back to proxying when the disk cannot sign URLs.
    Verification and reset emails never arrive Either MAIL_MAILER is still log, or no queue worker is running. Check storage/logs/laravel.log for the queued mail, then start php artisan queue:work.
    A settings change in .env has no effect Configuration is cached. Run php artisan optimize:clear.
    The checkouts succeed but no course appears for the student Nothing was enrolled because the payment was never finalized. Confirm the webhook endpoints are registered and reachable, then check the Payments list in the panel for the pending attempt.
    The storefront build fails on a page like /instructors That page is pre-rendered from live API data and the backend was unreachable. Start the API, then build again.
