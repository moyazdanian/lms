    Overview

    A complete, self-hosted learning platform in two applications: a Laravel API with a Filament admin panel, and a Next.js storefront. This manual covers what it does, how it is deployed with Docker, and how every screen fits together.

    Six chapters, about 35 minutes end to end. If you only want the site running, read Installation on a server and stop there.

    What this product is

    A marketplace for online courses. Instructors apply, build lessons, and earn a share of every sale. Students buy once and keep lifetime access to video, attachments, quizzes, and certificates. Administrators review courses, handle money and support, and edit the public site without touching code.

    The download contains two applications that share one database:

    • Backend — a Laravel 12 application that serves the REST API under /api/v1, owns the admin panel at /admin, stores and streams lesson media, talks to payment gateways, sends queued mail, and issues certificates.
    • Storefront — a Next.js 15 application that renders the public site (homepage, catalog, course pages, blog, checkout) and the signed-in dashboards for students and instructors.

    Everything a site owner normally wants to change at launch — name, logo, favicon, homepage sections, footer, legal text, cookie banner, payment gateways, instructor commission, payout methods, email templates' sender, and where lesson videos are stored — is edited in the admin panel or in one .env file.

    How the two applications fit together

    The storefront never talks to the database. It calls the API as the signed-in user, using Sanctum session cookies that the backend issues; the API enforces every permission, price, and access rule.

    Browser

    https://example.com — public pages, student dashboard, instructor workspace. Server-rendered by Next.js, then hydrated.

    Laravel API

    https://api.example.com/api/v1 — authentication, catalog, cart, checkout, enrollments, progress, quizzes, certificates, instructor authoring, payouts. Session cookie + CSRF for browser requests.

    MySQL 8

    Queue jobs, cache, and sessions use the same connection. No Redis or message broker is required.

    Private media

    The Docker storage volume by default, or any private S3-compatible bucket. Videos are never public files.

    Payment gateways

    Stripe, PayPal, Mollie, and Razorpay, enabled individually in the panel. Gateways call back after payment.

    Mail

    Verification, password resets, approvals, and payout decisions, sent through the SMTP account in .env.

    The admin panel lives on the backend host

    Filament renders at https://api.example.com/admin. Students and instructors never see it; they use the Next.js storefront only. Reach for the panel to approve a course, resync a payment, revoke a certificate, edit a gateway key, or change a legal page.

    How it is deployed

    The supported deployment is Docker Compose on a Linux server. Four containers run the whole platform, and Caddy obtains and renews HTTPS certificates automatically. Nothing is installed on the host except Docker.

    Container Runs
    mysqlMySQL 8.4, with its data on a named volume.
    apinginx + php-fpm + a queue worker. The REST API, /admin, uploads, and queued mail.
    webThe Next.js standalone server. The public site and both dashboards.
    caddyPorts 80/443, automatic TLS for both hostnames, and the reverse proxy that keeps cookies first-party.

    Two hostnames are required: the storefront (example.com) and the API with the admin panel (api.example.com). Both are set in one .env file, alongside the database passwords, the first administrator, and SMTP.

    The full procedure, including every environment key and the email setup, is in Installation on a server. This manual does not document a manual PHP/Node installation.

    Three roles, one platform

    Every account has one role, and each role sees a different surface.

    How each role is created and what it can reach
    Role How an account gets it What it can do
    Student Default for every new registration Browse and buy courses, watch lessons, track progress, take quizzes, earn and download certificates, review courses, keep a wishlist, open support tickets, and use the data-export or account-deletion API endpoints.
    Instructor Applied for from the storefront, approved by an administrator Everything a student can do, plus: build courses with a step-by-step authoring flow, manage curriculum, attachments, and the quiz, see sales and earnings, and request payouts.
    Admin Created by the first boot from ADMIN_EMAIL and ADMIN_PASSWORD Full control: users, instructors, courses and approvals, categories, coupons, orders, payments, enrollments, certificates, quizzes, content, legal text, support tickets, notifications, and every setting.

    Technology and versions

    The stack is deliberately mainstream: Laravel and Next.js, no proprietary runtime, nothing that needs a special host beyond Docker.

    Layer What runs there
    Front end Next.js 15.3 (App Router, React 19), Tailwind CSS 4, Radix UI primitives, TanStack Query 5 for data fetching, axios for API calls, Formik and Yup for forms, TipTap and BlockNote for rich text, Recharts for dashboards.
    Backend Laravel 12 on PHP 8.2+ (the Docker image runs 8.4), Filament 4 admin panel on Livewire 3, Sanctum 4 for cookie-based single-page-app sessions, Socialite for Google sign-in, barryvdh/laravel-dompdf for certificate PDFs.
    Database MySQL 8 (the stack pins 8.4.11) or MariaDB 10.4+. Queue, cache, and session drivers all use the database, so there is no Redis requirement.
    Payments Stripe, PayPal, Mollie, and Razorpay, switchable in the admin panel; zero-total checkout is supported for free or fully discounted carts. Every gateway is verified server-side before an order is finalized.
    Media Lesson videos live on a private disk: the Docker storage volume by default, or any S3-compatible bucket (AWS S3, Cloudflare R2, MinIO, DigitalOcean Spaces, Wasabi). Two delivery modes: stream through the app, or redirect to time-limited signed URLs.
    Email Laravel's SMTP transport, configured entirely in .env; queued through the database and delivered by the API container's worker.
    Testing Pest 3 on PHPUnit 11, with feature tests covering checkout, approvals, payouts, media access, certificates, and authentication.

    What ships in the box

    Two applications, the deployment stack, and this manual.

    lms/
├─ localhost/                     Laravel 12 application — API, admin panel, jobs, tests
│  ├─ app/Filament/                 admin panel: resources, pages, widgets
│  ├─ app/Http/Controllers/         public, auth, instructor, and webhook controllers
│  ├─ app/Services/                 payments, payouts, approvals, certificates, storage, progress
│  ├─ app/Console/Commands/         media:migrate-to-cloud — move media to a bucket
│  ├─ database/migrations/          schema, run automatically by the container entrypoint
│  ├─ database/seeders/             homepage content, features, default administrator
│  ├─ routes/api.php                every API route, all under /api/v1
│  └─ tests/Feature/                Pest feature tests
├─ frontend/                      Next.js 15 storefront and dashboards
│  ├─ src/app/(main)/               public site: catalog, course, blog, cart, checkout, legal pages
│  ├─ src/app/(dashboard)/          student and instructor areas behind the login
│  ├─ src/lib/api/                  one module per API area
│  └─ src/components/               UI: course detail, teaching tools, quiz, payments
├─ docker/                        Caddyfile and container configuration
├─ docker-compose.yml              the four-service stack
├─ .env.docker.example             the only configuration file to copy and fill
└─ documentation/                 this manual — open index.html in a browser

    The documentation is static HTML, CSS, and JavaScript with no build step. Open documentation/index.html directly, or serve the folder from any web server.
